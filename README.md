# Edgar Muoni · portfolio

My portfolio website: **https://edmuoni.github.io/**

Five pages: who I am, what I bring to a team, what I am building now, work I have finished and my
school projects. Every project also has a page of its own.

## Stack

- **Vue 3** with `<script setup>` and **TypeScript**
- **Vue Router** for the pages
- **Vite** for the dev server and the production build
- **GitHub Actions** builds the site and publishes it to **GitHub Pages** on every push to `main`

Fonts (Source Serif 4, Inter, JetBrains Mono) are bundled from npm, so the site makes no requests to
Google Fonts or any other third party.

## Run it locally

Needs Node.js 22.18+ or 24.12+.

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # type check, production build and pre-rendering into dist/
npm run preview    # serve the built site from dist/
```

## Project layout

The code is in `src/`. It flows in one direction: **data → components → views (pages) → router**.

```
src/
  data/          WHAT the site says: plain TypeScript objects, no HTML
    profile.ts     name, role, contact links
    career.ts      strengths, numbers, skills, experience, education
    projects.ts    every project; each one also gets its own page at /projects/<slug>
    mascot.ts      what Ohm, the mascot, says on each page
  components/    reusable pieces that display data (case study, project card, timeline, header …)
  views/         the pages; each one puts components together
    HomeView.vue  WhatIBringView.vue  NowBuildingView.vue  WorkView.vue  SchoolView.vue
    ProjectView.vue (one project's page)  NotFoundView.vue
  router/        which URL shows which page, plus each page's tab title
  composables/   shared logic without HTML (theme switch, motion switch)
  directives/    v-reveal: slide elements in as they scroll into view
  styles/        tokens.css = every colour and font; base.css = plain HTML elements;
                 motion.css = the motion rules
  App.vue        the frame around every page: header, page, footer
  app.ts         builds the Vue app and its router (used by both entry files below)
  main.ts        starting point in the browser: loads fonts and styles, starts Vue
  entry-server.ts  starting point for the build: renders one page to HTML in Node.js
```

Everything outside `src/` is setup, written once and rarely touched:

| File or folder | What it is |
|---|---|
| `index.html` | The HTML template every page is built from; the build puts each page's content into its `<div id="app">` |
| `public/` | Files copied to the site as they are (the favicon) |
| `package.json` | The project's dependencies and its `npm run …` commands |
| `package-lock.json` | Exact versions of every dependency, so every install is identical (generated) |
| `node_modules/` | The installed dependencies (generated by `npm install`, not in git) |
| `vite.config.ts` | Build settings: the Vue plugin, the `@/` path shortcut, one CSS file for the whole site |
| `scripts/prerender.ts` | The last build step: writes every page's finished HTML into `dist/` (see below) |
| `tsconfig.json` | TypeScript settings; it points to `tsconfig.app.json` (code in `src/`) and `tsconfig.node.json` (`vite.config.ts`, which runs in Node.js, not the browser) |
| `env.d.ts` | Tells TypeScript about Vite extras such as `import.meta.env` |
| `.github/workflows/deploy.yml` | Builds the site and publishes it to GitHub Pages on every push to `main` |
| `.vscode/extensions.json` | Recommends the Vue extension when the folder is opened in VS Code |
| `dist/` | The finished site after `npm run build` (generated, not in git) |
| `dist-ssr/` | The copy of the app the build runs in Node.js to pre-render the pages (generated, not in git) |

To add a project, add an entry to `src/data/projects.ts`. Its card, its own page at
`/projects/<slug>` and that page's pre-rendered HTML file all follow automatically.

## Every page is pre-rendered

`npm run build` runs three steps (see `package.json`):

1. `vite build` builds the app for the browser into `dist/`.
2. `vite build --ssr src/entry-server.ts` builds a copy of the same app that runs in Node.js, into `dist-ssr/`.
3. `node scripts/prerender.ts` uses that copy to render every page to HTML and writes it as a real file:
   `dist/index.html`, `dist/work/index.html` and so on, each with that page's own title and description.

This is called pre-rendering (or static site generation). It does three things:

- **The text is in the file.** The site reads fine with JavaScript turned off, and search engines and
  link previews see the real content.
- **Every address answers "200 OK".** GitHub Pages only serves files; without `dist/work/index.html` it
  would answer `/work` from `404.html` with the status "404 Not Found".
- **No second drawing.** When JavaScript runs, Vue *hydrates* the page: it attaches to the HTML that is
  already there instead of drawing it again.

`dist/404.html` holds the "page not found" view, for addresses that really don't exist.

Because the HTML is made in Node.js, code that runs while a component is being set up must not touch
`window`, `document` or `localStorage`; do that in `onMounted`, which only runs in the browser. If the
browser's first render differs from the HTML, Vue warns about a "hydration mismatch"; build with
`HYDRATION_DEBUG=1 npm run build` to see the details in the console.

To add a page: add it to `src/router/pages.ts`, give it a route in `src/router/index.ts`, and the
build creates its file.

## Motion, and the rules it follows

Every page moves: headings and leads type themselves, Ohm the mascot greets the visitor, circuit
traces draw themselves behind each page header, cards slide in as they scroll into view and lift on
hover, and a faint dot grid drifts behind the site. All of it follows the same rules (see
`src/styles/motion.css`):

- **Readable without JavaScript.** The pre-rendered HTML holds every word. Text is hidden for
  typing or sliding only when JavaScript runs, and a safety net in `index.html` shows it anyway if
  the app's script fails to start.
- **Reduced motion.** Visitors whose system asks for reduced motion, or who press the motion button
  in the header, get the finished page with nothing moving. Every animation is written so that an
  element's normal style is its finished look.
- **No layout shift.** Typed text always holds its full size (the part not typed yet is
  transparent, not missing), Ohm's bubble fits its longest line from the start, and only
  properties that never move other content are animated.
- **Accessible.** Screen readers always get the full text; the decoration is hidden from them.
- **Light.** CSS and SVG only, no animation library. Animations far off-screen are paused.
