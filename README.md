# Edgar Muoni · portfolio

My portfolio website: **https://edmuoni.github.io/**

Four pages: who I am, what I bring to a team, what I am building now, and work I have finished.

## Stack

- **Vue 3** with `<script setup>` and **TypeScript**
- **Vue Router** for the four pages
- **Vite** for the dev server and the production build
- **GitHub Actions** builds the site and publishes it to **GitHub Pages** on every push to `main`

Fonts (Source Serif 4, Inter, JetBrains Mono) are bundled from npm, so the site makes no requests to
Google Fonts or any other third party.

## Run it locally

Needs Node.js 22.18+ or 24.12+.

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # type check + production build into dist/
npm run preview    # serve the built site from dist/
```

## Project layout

The code is in `src/`. It flows in one direction: **data → components → views (pages) → router**.

```
src/
  data/          WHAT the site says: plain TypeScript objects, no HTML
    profile.ts     name, role, contact links
    career.ts      strengths, numbers, skills, experience, education
    projects.ts    every project on "Now building" and "Finished work"
  components/    reusable pieces that display data (case study, project card, timeline, header …)
  views/         the pages; each one puts components together
    HomeView.vue  WhatIBringView.vue  NowBuildingView.vue  WorkView.vue  NotFoundView.vue
  router/        which URL shows which page, plus each page's tab title
  composables/   shared logic without HTML (the light/dark theme switch)
  styles/        tokens.css = every colour and font; base.css = plain HTML elements
  App.vue        the frame around every page: header, page, footer
  main.ts        starting point: loads fonts and styles, starts Vue and the router
```

Everything outside `src/` is setup, written once and rarely touched:

| File or folder | What it is |
|---|---|
| `index.html` | The one HTML page the browser loads; Vue fills in its `<div id="app">` |
| `public/` | Files copied to the site as they are (the favicon) |
| `package.json` | The project's dependencies and its `npm run …` commands |
| `package-lock.json` | Exact versions of every dependency, so every install is identical (generated) |
| `node_modules/` | The installed dependencies (generated by `npm install`, not in git) |
| `vite.config.ts` | Build settings: the Vue plugin, the `@/` path shortcut, the GitHub Pages fallback |
| `tsconfig.json` | TypeScript settings; it points to `tsconfig.app.json` (code in `src/`) and `tsconfig.node.json` (`vite.config.ts`, which runs in Node.js, not the browser) |
| `env.d.ts` | Tells TypeScript about Vite extras such as `import.meta.env` |
| `.github/workflows/deploy.yml` | Builds the site and publishes it to GitHub Pages on every push to `main` |
| `.vscode/extensions.json` | Recommends the Vue extension when the folder is opened in VS Code |
| `dist/` | The finished site after `npm run build` (generated, not in git) |

To add a project, add an entry to `src/data/projects.ts`; the pages pick it up automatically.

## One HTML file per page

GitHub Pages only serves files. If there were no file for `edmuoni.github.io/work`, GitHub would answer
with `404.html` and the status "404 Not Found". The page would still appear, but link previews and search
engines would treat it as missing.

So after every build, `vite.config.ts` writes a real file for each page listed in
`src/router/pages.ts` (`dist/work/index.html` and so on). Each file carries that page's own title and
description, and GitHub answers "200 OK". `404.html` is still a copy of the app, for addresses that
really don't exist, so Vue Router can show its "page not found" view.

To add a page: add it to `src/router/pages.ts`, give it a route in `src/router/index.ts`, and the
build creates its file.
